Deploy

A new computer gets one program and one data folder. Employees open the desktop icon, or a bookmark.

Windows desk

On the desk computer, in PowerShell, run the install command from the HotelDruid release. The repository name is filled in on that release:

iex (irm https://github.com/<owner>/hotelDruid/releases/download/blazor-latest/install.ps1)

Approve the administrator prompt. That downloads HotelDruid-desktop.zip, installs the ASP.NET Core 10 runtime when it is missing, copies the program to C:\ProgramData\HotelDruid\app, keeps the hotel in data and the log in logs, and starts it at every boot. Open the desktop icon. The first page is House settings.

The same zip can be copied onto a computer that has no internet. Unzip it and run HotelDruid.cmd.

The address is https://localhost:5001/. The install creates a certificate for localhost. The private key stays in the machine personal store. The public certificate is added to the machine trusted root store.

Nightly copy

.\HotelDruid.cmd Install -BackupFolder "$env:OneDrive\HotelDruid-backups" -BackupAt 02:00

Run the same command again to change the folder or the time. .\HotelDruid.cmd Backup takes one copy now.

The task runs as the person who set it, and only while that person is signed in, so the folder can be OneDrive. Without this, the only copy is the data folder on that computer.

Logs are C:\ProgramData\HotelDruid\logs\api-yyyyMMdd.log. Copies and daily logs older than 30 days are removed. api-startup.log is the start-up console and is kept.

Remove

.\HotelDruid.cmd Uninstall writes an export into the current user's Temp folder, then removes the program, the task, and the icon.

Container

The hotel runs as one image. Open http://localhost:8080/. The hotel files are the /data mount. HOTELDRUID_PORT changes the host port. The commands for each scenario are in the container notes beside the compose files.

Plain

docker compose -f deploy/container/compose/plain.yml up --build. down -v deletes the named volume.

Keycloak

The same hotel image, plus the sign-in service. The steps are in the container notes.

Reverse proxy

The same hotel image, behind the proxy on ports 80 and 443. The proxy needs the certificate files.

Public

The proxy and Keycloak together. A certificate and the sign-in finish are in the deployment runbook and Keycloak.

Next: Demo hotel.

Demo hotel

Use this to train the team. Do not load it over a hotel that is already in use unless the export path has been kept.

  1. Install the desk. See Deploy.
  2. In an administrator PowerShell, in the unzipped folder:
powershell -NoProfile -ExecutionPolicy Bypass -File .\Load-DemoHotel.ps1
  1. The current hotel is exported first. The last line of the window is that path, under the current user's Temp folder.
  2. Reload the browser. The open page still shows the previous hotel until it is reloaded.

The demo is Hotel Belvedere: 20 rooms, about two thirds occupied, history from five years ago through six months ahead. The same seed writes the same pattern. Stays that already left are checked out. Stays that began before today and are still open are in house. Today and later stay confirmed.

Practice Reservations, Arrivals, In house, and Check-out on those stays. A stay you check in or pay on this copy is changed. Load the demo again only if the export from step 3 is still the hotel you want to keep.

Next: The desk.

The desk

Home is the day's work. Set the clerk name first. See People.

The menu on the left is the same work, grouped. Each page in this manual is one of those entries.

Next: Guests.

Guests

A stay needs a surname. The other fields are what the registration standard and the invoice ask for.

Clients

  1. Clients → new, or search and open.
  2. Record the name, the address, and the document fields the house standard requires.
  3. Save.

The guest record is the person. It is not the stay. The same person can return.

Other people in the room

  1. Booking Guests.
  2. Attach each other occupant to the booking.
  3. A card is printed per person on arrival. Night audit counts the names the standard requires.

Cancelled

Cancelled Bookings is the list of stays that were cancelled. Open one to read it. It is not a new reservation.

Next: Reservations.

Reservations

New stay

  1. Bookings → New.
  2. Fill the room, the arrival, the departure, the number of persons, and the guest surname.
  3. Save.

The price comes from the tariff for that room, those dates, and that number of people. See Rates. If no tariff applies, do not leave the stay without a price. An arrival with no tariff is a failed reservation.

The right-hand panel is the stay. Payments under the guest are a list: what was paid, and the date. The heading opens the money page.

Calendar

Calendar shows who is in which room. Use it to pick a free room before you save.

Rooms

Rooms is the house: name, beds, floor. A room that is missing here cannot be sold.

Received

Received holds bookings that arrived from a channel or a message and are not accepted yet. Accept the ones the house will honour. With inbox automation off, this is where those messages wait. See House settings.

Money on the stay

Open the stay, then the amount, or Payments.

Record a deposit or a payment with the amount, what it applies to, and who recorded it. A deposit is held until check-out. It is not the same as a payment against the stay. The bill's amount due already subtracts a deposit still held.

Taking money at the door, with a payment code, is Arrivals.

Next: Arrivals.

Arrivals

Arrived on the desk, or on the booking, opens this page. The guest is not in house until Mark arrived.

Left: this stay only. Back returns to the previous page. Middle: the work. Right: the same stay detail as the booking.

Registration card

  1. Open the letter for the language the house uses. The buttons are the copies under Letters.
  2. The card is already filled with the guest and the stay.
  3. Print it. The guest signs it. File the paper.
  4. Do not scan the identity document into the hotel. Check the card against the document, then type any missing field on the guest.

Which fields are required is the registration standard in House settings. Night audit lists the gaps.

Payment

  1. The amount starts as what is still due after any deposit.
  2. Choose cash, card, or transfer.
  3. Card and transfer need the code from the slip or the transfer. Type it. A terminal, when one is connected later, supplies the same code.
  4. Set the time if it is not now.
  5. Record payment. The code is stored on the ledger line so it can be matched to a terminal log.

Cash does not need a code. A card payment is not cash in the drawer.

Room actually taken

  1. Change the number of guests or the room when the party is not the one that was booked.
  2. The tariff for that room and that number must exist. See Rates.
  3. If you leave the room as booked, the price already on the stay is kept.
  4. Mark arrived.

A guest already in house can still print a card and record a payment here. The room change for someone already in house is In house.

Next: In house.

In house

These are stays in the Stays box on the desk.

Change the room

On the booking, move the guest from the date they change room. The tariff follows the room they take. A move is not a new reservation.

Extras on the stay

Booking Costs posts an extra on one stay, such as a cot or a late dinner charged to the room.

The kinds of extra, and the dates they apply, are Rates.

Counter sales

  1. Point of Sale.
  2. Choose the in-house stay, or a walk-up guest.
  3. Sell. Cash or card.
  4. A sale on a stay is charged to that guest and appears on the bill at check-out.

Name the drawer when you take money. See Cash.

Next: Check-out.

Check-out

  1. Open the stay from Departures on the desk, or from Bookings.
  2. Take any amount still due. Use the payment on Arrivals or the money page in Reservations. Put the slip code on a card or a transfer.
  3. Check out.

A deposit still held is applied to the stay at check-out. After that, the bill no longer shows it as money waiting. It has paid the stay.

  1. Print the invoice in the house language. See Letters.
  2. Print the receipt for what was paid.

The invoice total due is what the guest still has to pay. It is not the room price repeated next to the deposit.

Next: Night audit.

Night audit

Open Night audit after the departures are done.

The page lists what the day still misses: a registration field the standard requires, an open departure, a stay with no tariff.

Read the list. Fix the rows you can. Stamp the day when the list is accepted.

The stamp means the day was seen. It does not mean the guest paid. Do not stamp a day the house is still selling.

Next: Cash.

Cash

Drawers

Cash Registers is each drawer or terminal the desk uses. Open the one that is taking money before the shift. A payment recorded against a stay should name that drawer when the house keeps more than one.

Paid out

Expenses is money leaving the house: a supplier, a petty-cash purchase. Record the amount, what it was, and whether it counts toward the day.

What moved

Money History is the list of payments, sales, and paid-outs. Use it to match a payment code from Arrivals to a terminal slip.

A card payment is not cash counted in the drawer. The code on the ledger line is how the two are reconciled.

Next: Rates.

Rates

A price is a tariff plus the dates it applies, for a room and a number of guests.

Tariffs

  1. Tariffs → add the plans the house sells.
  2. Set the price and the dates.

Which room gets which plan

Assignment Rules binds a tariff to rooms. A room with no rule cannot be quoted. Reservations and Arrivals then have no price for that room.

Extras

Extra Costs is a charge that is not the room: breakfast, a cot, parking, and the dates it can be sold. Posting one onto a stay is In house.

Next: Accounts.

Accounts

The numbers are the chart chosen in House settings.

Ledger

General Ledger is every posted line. Guest charges, payments, deposits, tax, and expenses land here. A payment code from the desk is on the payment line.

Do not edit history to correct a price. Post the adjustment.

Chart

Chart of Accounts shows the numbers in use. Changing a number after postings exist splits the history across two codes.

Tax

Tax rates holds the percentages. When the house price is inclusive, the tax is inside the price. The invoice shows a recap. It does not add the tax a second time.

Reports

Reports is the printed lists: arrivals, in house, departures, and the cashier close. Open the one the shift needs.

Next: Property.

Property

Rooms that can be sold are under Reservations. This chapter is the rest of the building.

Assets

Assets is equipment the house tracks: a boiler, a vehicle, a large fitting.

Stores

Warehouses is where stock sits. Inventory is the items and the quantity.

Next: Letters.

Letters

Contract Templates holds the invoice, the receipt, the confirmation email, and the registration card. There is one copy for each language the house prints.

  1. Open the letter.
  2. Leave the sentences as the house wants them. The program does not translate the headings.
  3. Place a value field where a figure or a name should appear: the guest, the dates, the room, the amount due.
  4. Save.

The desk language in House settings does not choose which letter prints. The button the clerk presses does. Print the copy written in the hotel's language.

A registration card is filled the same way and opened from Arrivals. An invoice number is given to the invoice copies. A receipt does not take that number.

Messages is the inbox for those confirmations and for channel mail. Send from the stay when the guest should receive the letter. Do not use a live guest address while training on the demo.

Next: People.

People

Clerk name

On Home, Set your name, or open Profile. That name is written on ledger lines. Each browser can keep its own name, which is enough when several people share one desk without signing in.

Screen language

Settings changes the menus for this browser. English, Spanish, or Italian. It does not change letters and it does not change another person's browser.

When sign-in is on

Users, User Groups, and privileges exist when the hotel uses an identity provider. A desk with no sign-in hides that work and uses the profile name instead.

Roles and the public sign-in server are Keycloak. Putting the desk on a public address is the deployment runbook.
